# 发布包（publish package）约定

用户只在本地拿图文去发布，不跑分发流水线。每篇文章交付时，除了 `drafts/<NN>-<slug>/` 里的工作包，还要在 `out/` 下生成一个**发布包**。发布包是用户直接拿去用的东西，只放三样：

```
out/<N> <中文标题>/
├── <中文标题>.docx      Word 排版稿（宋体小四、首行缩进、标题分级、表格、配图带图注）
├── <中文标题>.html      网页版，图片用相对路径引用同目录下的 图片/
├── 图片/
│   ├── 01-封面.jpg
│   ├── 02-<配图名>.jpg
│   ├── 03-<配图名>.jpg
│   ├── 04-<配图名>.jpg
│   └── 05-<配图名>.jpg
└── （可选）<中文标题>.7z   用户自行打包，不要求代理生成
```

## 命名

- **子目录 = 序号 + 空格 + 中文标题**，例如 `1 佳康顺品牌故事`、`2 昆山租轮椅的真实经历`。
- 序号从 1 开始，**按交付顺序递增**，不复用、不跳号；新文章取现有最大序号 + 1。
- 目录名与文件名都用中文，不用 slug、不用连字符。目录名里只允许一个空格（序号与标题之间）。
- 图片统一两位编号前缀：`01-` 是封面，`02-` 起是正文配图，编号顺序必须与正文出现顺序一致。

## 内容要求

- 图片 5 张：1 张封面 + 4 张正文配图，全部来自公司知识库（`01-产品图` 等）或公司自有素材，不使用外部图库图。
- Word 稿与 HTML 必须同源：都从 `drafts/<NN>-<slug>/<slug>.md` 渲染，正文、标题、图注一字不差。
- HTML 里的图片路径指向 `图片/`，保证整个目录拷走后双击就能看。
- 正文不含价格（用户明确要求过），涉及价格处写"以门店当天报价为准"。

## 生成方式

1. 文章走完交付合同（Gate 1 至 5 通过）。
2. HTML：`blog_render.py` 渲染后，把 `src="<slug 目录里的图片名>"` 批量替换成 `src="图片/<中文图片名>"`，写入发布包。
3. Word：`workbuddy-docx` 的 S2 产文档版 HTML（`<style>` 里 `font-family` 首项写 `"SimSun","宋体"`、正文 `12pt` + `text-indent:2em`、标题用 `h1`~`h3`、图注用 `figcaption`），S3 用 `convert_doc.py` 转 docx。
   - **图片必须用 base64 data URI 内嵌**：相对路径 `images/x.jpg` 转换后 docx 里 0 张图。
   - 转换引擎把所有图片统一拉到 14.7cm 宽；竖长图先补白边把宽高比压到 ≥0.86，否则高度会超过 A4 版心。
4. 图片：从知识库下载后按 `01-`…`05-` 重命名，复制进 `图片/`。封面是 `hero.jpg` 的副本。

## 注意

- `out/` 下的 docx、html 被 WorkBuddy 预览面板或 Word 打开时会被锁，写入前先关闭预览，否则 `PermissionError`。
- 用户可能会自己改 docx 或重命名子目录（例如加序号、打包 7z）。以用户改后的文件为准，后续修订要基于他改过的版本，不要覆盖回旧版。
