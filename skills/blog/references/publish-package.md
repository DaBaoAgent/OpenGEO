# 发布包与图文流水线（本仓库定制）

用户只在本地拿图文去发布，不跑分发流水线。每篇文章交付时，除了 `drafts/<NN>-<slug>/` 里的工作包，还要在 `out/` 下生成一个**发布包**。

## 一、发布包结构

```
out/<N> <中文标题>/
├── <中文标题>.docx      Word 排版稿（宋体小四、首行缩进、标题分级、表格、配图带图注）
├── <中文标题>.html      网页版，图片用相对路径引用同目录下的 图片/
└── 图片/
    ├── 01-封面.jpg
    ├── 02-<配图名>.jpg
    └── …
```

已发布的内容由用户自己归档到 `out/@<账号>已发<类型>/<N> <标题>/`（例如 `@心悦已发品牌`、`@小冯已发种草`）。新稿一律先放 `out/<N> <标题>/`，不要替用户归档。

## 二、命名与编号

- **子目录 = 序号 + 空格 + 中文标题**，例如 `1 佳康顺品牌故事`、`9 轮椅尺寸怎么量`。
- 序号**按交付顺序递增**，不复用、不跳号。**出包前先 `ls out/` 看现有最大序号**——用户会自己占号（本项目里 5、6 就是用户自己建的），不要从 1 开始数。
- 目录名与文件名都用中文，不用 slug、不用连字符；目录名里只允许一个空格。
- 图片两位编号前缀：`01-` 封面，`02-` 起正文配图，编号顺序与正文出现顺序一致。
- 序号 + 中文名里如果混排阿拉伯数字被安全策略拦截（`out/4 买轮椅避坑5件事` 曾被拒写），换一个不带数字混排的标题即可。

## 三、内容形态（两套，按用户当次要求选）

| | A. 品牌 / 种草 / 评测 | B. 干货 |
|---|---|---|
| 结尾 | 两个取车点 + 热线 + 租赁微信 + 资料来源清单 | 只留一句轻描淡写的品牌/产品提及 |
| 联系方式 | 有（地址、400 电话、微信号） | **不写地址、不写联系方式、不写网址、不写资料来源** |
| 语气 | 确定式，不用"可能/大概/通常/多半/口径"这类模糊词 | 同左 |
| 价格 | 不写具体价格，写"以门店当天报价为准" | 同样不写 |

用户明确要求过：**干货篇只要价值，不要转化尾巴**。写 B 类时，正文里连官网链接也不要出现。

## 四、图片规则

- 数量：1 张封面 + 3 到 4 张正文配图。素材充足时按 5 张（1+4）出，素材不足时 4 张（1+3）也可以，不要为凑数复用。
- **一次性使用，不复用。** 一张素材（含它派生的封面、裁切图）只能用在一篇图文里。出包前查 `out/图片使用登记.md` 的"已用素材"表，出包后立刻登记：源文件路径、用在哪篇、用作哪张、备注。登记以**知识库源文件**为准，封面由哪张源图合成也要写明。
- 素材来源优先级：
  1. 公司知识库 `01-产品图`（`kb_client.py get --path … --out …`）
  2. 本地已存档的知识库副本（`drafts/*/kb/assets/…`）
  3. **PIL 自绘示意图**（干货类首选，见第五节）
- 不使用外部图库图。带价格文字的素材（如 `14 昆山成片/1.png`、`2.png`）不用。
- 知识库文件服务经常返回 `Remote end closed connection`（`/api/get` 直接 000）。下载失败就换图，不要死磕；同一批连续失败时改走本地副本或自绘图。

## 五、自绘示意图（干货类）

干货篇的图用 PIL 画，比产品实拍更贴题（读者能照着量）。约定：

- 画布 `1200×800`，白底；线条 `#0d273e`，尺寸箭头 `#f5a623`，辅助文字 `#6b7a89`。
- 字体：标题 `msyhbd.ttc`（微软雅黑 Bold），标注 `msyh.ttc`。
- 每张图一个主题：座宽座深（俯视）、扶手高靠背高（侧视）、环境尺寸、门槛斜坡、扶手位置、床边高度。
- 尺寸标注用双向箭头 + 端点文字，不要只写数字不画线。
- 封面版式：左侧深色面板放标题（kicker + 3 行大字 + 2 行副标），右侧浅灰面板放一张白卡，卡内嵌示意图。
- 自绘图不计入素材台账，但每篇的标注内容要不一样。

## 六、Word 生成链路（已验证）

```
drafts/<NN>-<slug>/<slug>.md
   → 文档版 HTML（S2）          宋体 12pt / 行高 1.75 / text-indent:2em
   → 图片 base64 内嵌           data:image/jpeg;base64,…
   → convert_doc.py            --no-preflight --no-verify
   → out/<N> <标题>/<标题>.docx
```

一键脚本：`scripts/build_publish_package.py`

```bash
python scripts/build_publish_package.py \
  --draft drafts/08-wheelchair-measurements \
  --out-name "9 轮椅尺寸怎么量" \
  --image-map "hero.jpg=01-封面.jpg;02-seat-size.jpg=02-座宽座深.jpg;…"
```

参数说明：

| 参数 | 作用 |
|---|---|
| `--draft` | 草稿目录，脚本自动取里面唯一的 `*.md`（排除 `review.md`） |
| `--out-name` | 发布包名，**必须带序号**；脚本用"空格后"的部分做 docx/html 文件名 |
| `--image-map` | `源文件名=中文图名` 用 `;` 分隔；`hero.jpg` 固定映射到 `01-封面.jpg` |

脚本内部做的事：缩图（长边 >1400px 缩到 1400）→ 竖图补白边（宽高比 >1.55 时补到 0.86）→ 图注拆成独立 `<p class="cap">` → base64 内嵌 → 调 `convert_doc.py` → 改写 HTML 的图片路径为 `图片/…`。

### 三个必须知道的坑

1. **图注会被并进标题。** 若把 `<figcaption>` 留在 `<figure>` 里，转换后图注会粘到下一个 H2 上，出现"图：佳康顺选车：手动还是电动，看三件事"这种脏标题。脚本已改成图注独立成段，不要改回去。
2. **图片必须 base64 内嵌。** 用相对路径 `images/x.jpg`，转出来的 docx 里 0 张图。
3. **偶发空文档。** `convert_doc.py` 有时返回 `success: true` 但 docx 只有 5KB、`document.xml` 185 字节（正文为空）。处理办法：先转到临时路径（如 `output/t.docx`）验证有内容，再 `cp` 覆盖目标文件。

其他约束：

- 转换引擎把所有图片统一拉到 14.7cm 宽，宽度属性不生效；竖长图必须提前补白边。
- 正文段落必须写 `text-indent:2em`，不写就没有缩进。
- `font-family` 首项必须是 `"SimSun","宋体"`，写系统别名会让 Word 回退默认字体。
- 标题用 `h1`~`h3`，转换后带 `heading 1/2/3` 样式（styleId 是数字，但 name 正确，大纲级别正常）。

## 七、质量门禁

出包前跑：

```bash
python scripts/blog_preflight.py --draft drafts/<NN>-<slug> --gate 2
python scripts/blog_preflight.py --draft drafts/<NN>-<slug> --gate 3
python scripts/blog_preflight.py --draft drafts/<NN>-<slug> --gate 5
```

- Gate 2 格式完整、Gate 3 三视口截图、Gate 5 资源与链接。B 类干货篇通常没有外链，Gate 5 秒过。
- Gate 4 需要独立 reviewer 打分（≥90 且零 Critical），按需跑；跑之前要 `--init-review-nonce`，reviewer 报告存 `review.md`。
- 引用百度百科会在 Gate 5 报 403，把 `external-links.allowed` 放到该 draft 目录，条目从 HTML 里反拷实际 `href`（手打会差字符，豁免不生效）。

## 八、同步发布（wechatsync）

生成好的 md/html 可以直接推到各平台草稿箱：

- MCP 服务名 `wechatsync`，工具 `list_platforms` / `check_auth` / `sync_article` / `extract_page`。
- 同步一律落**草稿**，不直接发布；图片能否自动上传取决于平台，微信、小红书要人工看一眼。
- 前提：Chrome 开着、插件「CLI / MCP 连接」为绿色「等待连接」；9527 端口独占，同一时间只能跑一个任务，多平台要一次调用传完。

## 九、文件占用

- `out/` 下的 docx、html 被 WorkBuddy 预览面板或 Word 打开时会被锁，写入前先关闭预览，否则 `PermissionError`；Word 的 `~$xxx.docx` 是锁文件，别去读。
- 用户会自己改 docx、重命名子目录、打包 7z。**以用户改后的文件为准**，后续修订基于他改过的版本，不要覆盖回旧版。
